# Architecture

DarQ Reborn is a single-activity View-system app (ViewBinding, Navigation component, Koin) that turns Android Force Dark on for chosen apps. The UI process only edits settings and talks to a privileged service that does the real work.

## Modules and processes

* `app` is the main shipped module. `systemstubs` holds compile-only stubs for hidden APIs. `testing/forcedark-probe` is a fixture app used by the device suites and published as an optional verification APK (`DarQ-Probe.<version>.apk`) attached to each release.
* The UI runs in the main process. The privileged work runs in a separate `:service` process started by Shizuku (user service) or by libsu (root service). Both expose the same AIDL interface `IDarqService`.
* `providers/DarqServiceConnectionProvider` binds that service. It prefers Shizuku, falls back to root, serializes binds with a mutex and reports the connected mode (`connectedServiceType`).
* Xposed mode is a third, optional path. `Xposed.kt` (LibXposed 101) and `XposedLegacy.kt` (API 82) hook `SystemProperties` inside each scoped app process so apps that opt out of Force Dark still get it. The default build ships only the legacy entry.

## Control flow

* A settings change writes to `DarqSharedPreferences`, which also writes a revisioned snapshot to `files/settings_snapshot.json` so a lost preferences file can be restored.
* `ContainerSharedViewModel` queues the change as an IPC setting and syncs it to the service. The snackbar shows the sync state.
* The service watches the foreground app and flips the system force dark property for selected apps. Auto Dark (`service/autodark`) schedules system dark mode by time, sunset and sunrise or by following the system theme.
* The app picker reads `components/apps/InstalledAppsRepository`, which keeps the sorted list in memory and in `files/app_list_cache.json` and refreshes only packages reported by `PackageManager.getChangedPackages`.

## UI structure

* `ui/screens/container` hosts the collapsing app bar, the navigation host, the loading screen and the snackbar. The app bar is sized with the status bar height at first layout and starts expanded so the title never jumps.
* `ui/screens/settings` builds screens from `SettingsItem` lists rendered by `SettingsAdapter`, with grouped rounded sections and `SettingsIcons` for the round icons.
* Bottom sheets extend `BaseBottomSheetFragment`, which blurs the app window behind the sheet through `providers/blur`. Dialogs use `ui/utils/DialogBlur.showBlurred` for the same blur.
* `components/theme` applies night mode in the Application and the accent and pure black overlays in `DarqActivity.onCreate` before `super.onCreate`. `ThemeManager.signature()` triggers `recreate()` when the choice changes.

## Diagnostics

* `components/diagnostics/CrashReporter` writes Java crashes to private storage and reads native crashes and ANRs from `ApplicationExitInfo` on Android 11 and later. A crash is offered once on the next launch.
* `DiagnosticsLog` filters the own-uid logcat, `DiagnosticsText` redacts it (hashed app packages, no coordinates or emails) and builds the prefilled GitHub form links under an 8000 character limit.
* `ui/screens/bottomsheets/report/ReportBottomSheetFragment` builds and previews the report itself, so it survives recreation and process death.

## Key Design Decisions

* Shizuku, root and Xposed stay separate paths behind one AIDL interface, so behavior in Shizuku mode never changes when the others are touched.
* The legacy Xposed entry is the default because LSPosed 1.9.2 prefers `META-INF/xposed/java_init.list`, fails to construct the LibXposed entry and then never loads `assets/xposed_init`.
* Root mode rebinds the surviving libsu daemon instead of calling `RootService.stop()` first, which raced the daemon after a force-stop and ended in "Service Timeout".
* Accent presets are generated by `scripts/theme/generate_accents.py` from the canonical seeds, never edited by hand. Stored preset keys are never renamed.
* All links open through `utils/Links.kt` (`LinkOpener`) and all toasts through `utils/Toasts.kt`. A unit test fails on new direct `Toast.makeText` or `URLSpan` use.
* New `SettingsBackup` fields must be nullable because Gson ignores Kotlin default values.

## Testing

* JVM and Robolectric unit tests live in `app/src/test` (theme, diagnostics, color math, links, translations, dialogs and layouts in every accent).
* `scripts/device` holds the device suites (`e2e_regression.py`, `e2e_xposed.py`, `e2e_diagnostics.py`) and `run_matrix.py`, which drives the emulator fleet and the two physical devices. See `scripts/device/README.md`.

## Known constraints

* Force Dark uses hidden APIs, so DarQ cannot be on the Play Store.
* Android samples the system force dark switch once per window, which is why a Samsung Pop-up View title bar can stay light for the first seconds (see the FAQ).
* Root and Xposed are only tested on disposable emulators, never on the physical devices.
